# E1 · appends a session event type that appears nowhere in the official packages

- **Level:** error
- **Source:** dsh plugin-development / references/practices.md

## What it checks

Detects `session.append("ns/type", ...)` when the literal first argument is outside the harvested event catalog.

## Why it matters

A Session.append() cannot set `ignorable: true`; a log holding an unknown type can refuse to reopen. The catalog is harvested from the official packages, not a specification.

## Boundary

The rule only reads the literal first argument. A computed type (`append(type, ...)`) is a static-analysis boundary, not a finding; the catalog's coverage is stated in the report's `limits` and in `ruleset.eventCatalog`.

The catalog carries the DSH versions it was harvested from. When `--dsh-version` names a host newer than the catalog's newest recorded version, an unknown type is downgraded to **warn** with the catalog coverage in the message: the type may exist on that host, the catalog simply cannot see it. Re-harvest with `npm run harvest:events` against the new host to restore the error level.
